Why Byte-Offset AST Splicing Outperforms Full DOM Serialization

An engineering retrospective on building a non-destructive in-browser HTML editor that leaves your original comments and template tags intact.

VS

Valentin Sorokin

Lead Compiler Architect

Visual website editors typically share a fatal architectural flaw: they parse your markup into an internal tree structure, execute mutations, and then serialize the document back into a string using generic serializers like innerHTML.

Key Principle

Never mutate code you did not touch. If the user edited a button's padding, adjacent comments, indentation, and template tags must remain bit-for-bit identical on disk.

The Parse5 Source Location Solution

Parse5 provides exact character offsets for every token when configured with sourceCodeLocationInfo: true. This allows us to calculate exact byte ranges for attributes:

// Surgical string slicing at exact coordinate offsets:
const before = html.slice(0, attrLoc.startOffset);
const after = html.slice(attrLoc.endOffset);
return before + `class="${newClasses}"` + after;

By operating strictly on character offsets, server templates (Blade, PHP, Twig) and HTML comments are never subjected to DOM tree normalization.
